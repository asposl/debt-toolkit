# 底稿工具箱GUI 使用说明

> 版本：2026-08 ｜ 运行环境：Windows 10/11 + Python 3.13（Tkinter 为 Python 自带，无需额外安装）

## 一、启动与界面总览

在 `底稿处理工具` 目录下执行：

```powershell
python 底稿工具箱GUI.py
```

窗口分为三部分：

```
┌──────────────────────────────────────────────┐
│  页签区：签章页工具 | 替换底稿内容 | 比较文件夹内容   │
│          底稿PDF材料整理 | 目录生成              │
├──────────────────────────────────────────────┤
│  运行日志：实时显示子进程输出（所有页签共用）        │
├──────────────────────────────────────────────┤
│  [清空日志] [打开底稿处理工具目录]   状态栏：就绪    │
└──────────────────────────────────────────────┘
```

通用操作：

- 所有路径输入框旁都有 **浏览…** 按钮；也可以直接在框里粘贴/编辑路径。
- **路径自动记忆**：每次点「执行」或关闭窗口时，所有输入框的值保存到
  `.zcode/gui_settings.json`，下次启动自动恢复。
- **同一时刻只运行一个任务**。任务运行期间所有执行按钮置灰，
  状态栏显示"运行中"；结束后恢复。
- 每个功能的**明细日志**仍按原规则写入各自模块的 `logs\` 文件夹，
  界面日志只是实时镜像。

## 二、页签①：签章页工具

对应模块：`签章页工具\pdf_toolkit.py`。处理一条完整的项目流水线。

### 参数

| 字段 | 说明 |
|---|---|
| 项目根目录 | 本项目底稿所在根文件夹。format/header/export/insert 都在这里面递归工作 |
| 项目标识 | 如"示例""示例"，拼进日志和清单文件名，用于区分项目 |
| 公司关键字 | 公司全名关键字，export 靠它识别需要拆末页的 PDF |
| 页眉只检查不修改 | 勾选后 ② 只输出检查报告，不改文件（dry-run） |
| format 仅处理最近N天 | 只格式化最近 N 天内更新的 docx，默认 100 |
| export PDF复用天数 | 最近 N 天生成的 PDF 直接复用不重导出，0 = 全部重导 |

### 六个步骤按钮

| 按钮 | 做什么 | 安全提示 |
|---|---|---|
| ① 刷新docx格式 | 黑体标题+宋体正文+Arial西文，1.5倍行距 | **原地修改** docx |
| ② 页眉修复 | 文件名编号与页眉编号比对、替换、补建 | 默认会改文件，可先勾 dry-run |
| ③ 导出PDF拆签章页 | Word→PDF 全量导出，拆末页合并成 签章页.pdf，生成清单 | 弹确认框；**不要重复跑**（见下） |
| ④ 过滤索引清单 | 从 no_company JSON 中过滤含"索引"条目 | 只读，生成新清单 |
| ⑤ 追加签章页 | 把 签章页.pdf 第 i 页追加到清单第 i 个 PDF 末尾 | 修改 PDF |
| ⑥ 替换签字页 | 用 签字合并.pdf 第 i 页替换无索引文件末页 | 数量不等时拒绝执行，弹确认框 |

⚠️ **重要**：③ 不要连续跑两遍——拆过末页的 PDF 被复用时末页已不含公司名，
会把 has_company 清单冲空、insert 对不上号。需要重导时：
先把项目根目录下的旧 PDF 删掉，或把"export PDF复用天数"设为 0。

### 初始化底稿文件

对应脚本：`签章页工具\初始化底稿文件.py`。位于同页签下方区块，用于项目
底稿的批量预处理：

| 字段 | 说明 |
|---|---|
| 待处理 Word 文件夹 | 要批量处理的 docx 根文件夹（递归子文件夹） |
| 发行人 | 签章落款的公司名 |
| 项目组 | 如"示例项目组"，写入落款行 |
| 落款日期 | 如"2026年6月   日"（日期留空待手填） |
| 汇总签章页文件名 | 所有独立签章页汇总输出的 docx 名，默认"全部签章页.docx" |

处理逻辑（对每个 docx）：

1. 全文统一字体（中文宋体/英文 Arial）、1.5 倍行距、页眉五号字、删除文末图片；
2. **末尾 50 字含「项目组」**：把最后的项目组行和日期行改写为界面上填的
   项目组/落款日期（右对齐），并删除其后多余段落；
3. **不含「项目组」**：在文末追加独立成节的签章页
   （"（本页无正文，为《标题》之签章页）"+ 发行人 + 日期），同时把该签章页
   汇总进「汇总签章页」文档。

⚠️ **原地修改、不可撤销**：点击后有确认框，请务必先备份原文件夹。

## 三、页签②：替换底稿内容

对应模块：`替换底稿内容\replace_toolkit.py`。规则全部来自根目录的
`替换规则表.xlsx`（「短替换」「长替换」两个工作表），界面只负责选目录。

| 控件 | 说明 |
|---|---|
| 替换规则表.xlsx | 默认指向工具包根目录的规则表 |
| docx 根目录 | short 和 long 共用的被处理目录（递归子文件夹） |
| 输出目录（short） | 留空 = 原地替换；填了则另存 |
| 素材 docx 文件夹（long） | 规则表 C 列素材文件的查找目录 |
| 覆盖原文件（long） | 勾选=原地覆盖；不勾=另存到下方输出目录 |
| 另存输出目录（long） | 不覆盖模式下的保存位置 |

- **短替换**：python-docx 引擎，快；跨 run 安全替换正文/表格/页眉页脚；
  查找词以 `regex:` 开头表示正则，替换词留空表示删除。
- **长替换**：Word COM 引擎，保格式；按"起始关键字…结束关键字"定位区间，
  删除后插入素材 docx。**需要本机装有 Microsoft Word**，每个文件都要启动
  Word 定位与粘贴，速度慢属正常，建议小批量先试。

## 四、页签③：比较文件夹内容

对应模块：`比较文件夹内容\folder_toolbox.py`（纯标准库）。

### 比较 / 合并

| 按钮 | 行为 |
|---|---|
| 比较差异（SHA-256） | 递归比较 old / new 两个母文件夹中的 docx，按相对路径+哈希列出三类差异；只读不改文件 |
| 合并（new 覆盖 old） | 按文件名匹配，用 new 里的最新版覆盖 old；**不备份**，点击前有确认框 |

### 提取打印文件

把多级文件夹里的 doc/docx 平铺复制到一个文件夹，方便批量打印：

| 控件 | 说明 |
|---|---|
| 源目录 | 默认联动"new 文件夹"的内容 |
| 输出目录 | 默认 `比较文件夹内容\打印文件` |
| 加序号前缀 (001_) | 按资源管理器习惯排序后加序号（支持中文序号 第十章 > 第九章）；重名自动改名 `xxx__2.docx` |
| 执行前清空输出目录 | 只清输出目录里的 Word 文件，不动其他类型 |

## 五、页签④：底稿PDF材料整理

对应模块：`底稿pdf材料\file_toolkit.py`。顶部下拉框切换功能，参数表单随之变化：

| 功能 | 用途 | 关键参数 |
|---|---|---|
| dedup_folders 编号子文件夹去重 | 按内容指纹对编号子文件夹去重并复制到输出目录（源不动）；layout 选 nested 处理"母/子"两层结构 | 源目录、输出目录 |
| convert_images 图片转PDF | 递归把 jpg/jpeg/png/jfif 转 PDF 并删除原图 | 目标目录 |
| match_excel 台账匹配 | Sheet1/Sheet2 按字段匹配，加 num 列、导未匹配 CSV | 台账 xlsx、匹配列 |
| merge_pdfs 特征优先级合并 | 按 num 定位编号文件夹，按 合同→担保→决议→借据 优先级合并 PDF | 匹配结果 xlsx、文件夹根目录、输出目录 |
| pdf_merge 子文件夹合并铺平编号 | 两阶段：先合并人工核对，再铺平连贯编号 | 顶级文件夹、编号前缀、阶段下拉 |
| flat_rename 多文件夹平铺重命名 | 多个子文件夹各自平铺/原地重命名 | 父目录、`目录名[:flat],…` 清单 |
| order_rename 固定位置顺序编号 | 多个固定位置的 PDF 按给出顺序全局连贯编号 | 位置目录（每行一个）、前缀 |
| renumber_files 重连贯编号 | 把已有"N 名称.pdf"的文件夹重排为 1/2/3… | 目标文件夹、起始编号 |

⚠️ **安全机制（沿袭原 CLI）**：flat_rename / order_rename / renumber_files /
pdf_merge 默认**仅预览**，日志里会列出改名计划；核对无误后勾选
「实际执行」再跑一次才落盘。特别注意 pdf_merge 的"仅铺平(--flatten)"
会删除子文件夹内的原始 PDF，不可恢复。

## 六、页签⑤：目录生成

对应模块：`多级文件夹生成目录\输出文件目录.py`。

1. 选择**目标文件夹**后，Excel/Word 输出路径会自动建议为同级目录下的
   `【项目名】目录.xlsx` / `【项目名】目录.docx`（可手动改）。
2. 点 **生成 Excel 目录** 或 **生成 Excel + Word 目录**。

生成规则：递归扫描多级结构 → 删除无任何文件后代的空文件夹 →
同文件夹内同编号去重（取名称更长者）→ 中文序号自然排序
（第九章 < 第十章）→ 层级表导出；Word 版由 Excel 转出（文件夹加粗）。

## 七、常见问题

**Q：点了按钮没反应？**
看状态栏。若显示"正在运行"说明上一个任务还没结束；若日志区出现报错，
按报错信息检查路径。

**Q：任务能中途取消吗？**
没有单独的取消按钮；直接关窗口会尝试终止当前任务。

**Q：换新项目要改哪里？**
只需改页签①的三项：项目根目录、项目标识、公司关键字，其余保持默认。
各模块 `toolkit/config.py` 里的原始配置不会被 GUI 改动。

**Q：界面上的设置存在哪？删了会怎样？**
`.zcode/gui_settings.json`，删除后下次启动回到默认值，不影响功能。

**Q：明细日志在哪？**
- 签章页工具：`签章页工具\logs\`
- 替换底稿内容：`替换底稿内容\logs\`
- 比较文件夹内容：`比较文件夹内容\logs\`
- 底稿PDF材料整理：`底稿pdf材料\logs\`
- 目录生成：不产生日志文件，结果直接写输出路径

**Q：某个功能想用命令行单独跑，还能吗？**
可以。GUI 只是外壳，原有入口（`pdf_toolkit.py`、`replace_toolkit.py`、
`folder_toolbox.py`、`file_toolkit.py` 等）完全不受影响，用法见各自 README。

## 附：实现结构（供维护参考）

| 文件 | 作用 |
|---|---|
| `底稿工具箱GUI.py` | Tkinter 主程序，5 个页签 + 日志区 + 设置持久化 |
| `gui_runner.py` | 子进程任务中转器：接收 JSON 任务描述，覆写目标模块 config 后调用其命令函数 |
| `.zcode/gui_settings.json` | 界面输入值记忆文件（自动生成） |

为什么经子进程中转：① 各模块的实现包同名（多个 `toolkit`），独立子进程彻底隔离；
② 配置型模块（签章页/替换）的路径写在各自 `config.py` 里，中转器按 GUI 参数
动态覆写，**不改任何原有代码**；③ Word COM 等重资源操作崩溃不会拖垮界面。
