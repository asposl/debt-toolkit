# 提取签字页 使用说明

`收集签字页.py` —— `insert --mode replace`（原 插入签字页.py）的**逆向操作**。

正向链路里，`pdf_toolkit.py insert --mode replace` 按 `no_company_无索引_latest.log` 清单，把 `签字合并.pdf` 第 i 页替换进清单第 i 个文件的末页。本脚本反向收拢：读同一份清单，把每个文件被插入的末尾签字页重新抽取出来，按原始文件名逐个单独输出，方便单独查阅或另行归档。

## 一、环境要求

- Windows 10/11 + Python 3.13
- 第三方依赖：`pypdf`（与 pdf_toolkit 共用）
- 需与 `pdf_toolkit.py` 位于同一目录运行（复用 `toolkit` 包的配置与日志模块）

## 二、抽取规则

| 源 PDF 页数 | 抽取内容 |
|---|---|
| 奇数（2n+1）页 | 最后 1 页 |
| 偶数（2n）页 | 最后 2 页 |
| 0 页（空文件） | 跳过，日志记为失败 |

单页文件属于奇数（1 = 2×0+1），正常抽取其唯一一页。

**全程只读源文件，不改动任何原 PDF。**

## 三、用法

```powershell
# 全部走默认配置（根目录、清单均取 toolkit/config.py 的 REPLACE_* 配置）
python 收集签字页.py

# 指定项目根目录（正式盘路径与本机不一致时必加）
python 收集签字页.py --root "示例项目根目录"

# 指定输出文件夹
python 收集签字页.py --root D:\proj --output-dir D:\proj\收集结果

# 指定清单文件
python 收集签字页.py --list no_company_无索引_latest.log
```

### 参数说明

| 参数 | 缺省值 | 说明 |
|---|---|---|
| `--root` | `config.REPLACE_ROOT_DIR`（= `PROJECT_ROOT`） | 项目根目录。清单内是相对路径，必须配合根目录才能定位实际文件 |
| `--list` | `config.REPLACE_LIST_PATH`（`no_company_无索引_latest.log`） | 路径清单；相对路径找不到时自动尝试 `logs\` 目录 |
| `--output-dir` | `<根目录>\收集签字页` | 输出文件夹；不存在会自动创建 |

## 四、输出逻辑

- 每份源 PDF 的抽取结果**单独成文件，沿用原始文件名**。
  例：`第一章\xxx\1-2-3 核查记录.pdf` → 输出文件夹中的 `1-2-3 核查记录.pdf`
- **同名兜底**：不同子文件夹出现同名 PDF 时，后写入的自动追加 `_2`、`_3` 后缀并在日志中告警，不会互相覆盖。对应关系以日志为准。
- 写入采用临时文件 + `os.replace` 原子写，中断不会留下半截文件；重跑会覆盖输出文件夹里的旧结果。

## 五、清单格式

与 `insert --mode replace` 完全同源（共用 `_load_path_list`）：

- `.json`：export 生成的字符串数组
- `.txt` / `.log`：逐行一条相对路径；旧版文件末尾的「统计信息」块会被自动跳过

## 六、行为约定

- **失败不中断**：某个文件缺失、损坏或为空时记日志跳过，继续处理其余条目；结束时汇总"失败明细 - 清单第几条"，便于回查。
- **退出码**：全部成功返回 0；有任何失败返回 1（但成功的文件照常输出）。
- 一个都没成功时不产出结果。

## 七、日志

每次运行在脚本同级 `logs\collect_<项目标识>_<YYYYMMDD_HHMM>.txt` 生成日志，控制台与文件内容一致。每条记录包含：序号、完整目标路径、总页数、奇偶判定、抽取页数、输出文件名。

## 八、常见问题

**Q：提示"目标文件不存在"？**
清单里是相对路径，本机没有对应的盘符/目录。用 `--root` 指向实际项目根目录；若清单本身过期，先重跑 export/filter 链路生成新清单。

**Q：输出文件夹里出现 `xxx_2.pdf`？**
清单中有两个不同目录下的同名文件，第二个自动改名避免覆盖。哪个条目对应 `_2` 文件，看日志中"[告警] 清单第 N 条的文件名与之前条目重复"。

**Q：会不会改坏原文件？**
不会。脚本对源 PDF 只有读操作，所有写操作都发生在输出文件夹。

**Q：和合并版有什么区别？**
早期版本把所有抽取页合并成一份新 PDF；现按需求改为按原始文件名单独输出。如需合并件，可用 pypdf 或既有 `merge_pdfs` / `pdf_merge` 工具对输出文件夹二次合并。

## 九、验证情况

已通过临时样例端到端验证：

- 单页文件 → 输出该 1 页
- 3 页（奇数）→ 末 1 页；4 页 / 2 页（偶数）→ 末 2 页
- 输出文件名与原始文件名一致，页序与来源正确
- 清单含缺失文件 → 跳过并汇总、退出码 1；全部存在 → 退出码 0
- 跨目录同名文件 → 自动 `_2` 后缀 + 告警
- 旧版 `.log` 末尾统计块正确过滤
